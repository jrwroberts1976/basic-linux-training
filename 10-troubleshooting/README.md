# Overview

Troubleshooting is one of the most important skills for Linux administrators, cloud engineers, and DevOps professionals.

Linux systems can fail in many different ways:

- Services stop working
- Applications become unavailable
- Systems run slowly
- Storage becomes full
- Network connections fail
- Authentication problems occur

Effective troubleshooting requires a structured approach.

This module introduces the tools and techniques used to identify, analyse, and resolve Linux problems.

# Troubleshooting Methodology

A good troubleshooting process follows:

```text
Identify Problem

        |

Gather Information

        |

Analyse Evidence

        |

Test Possible Causes

        |

Apply Fix

        |

Verify Solution

        |

Document Results
```

---

# Common Troubleshooting Commands

| Command | Purpose |
|---|---|
| `top` | View processes and CPU usage |
| `ps` | Process information |
| `systemctl` | Manage services |
| `journalctl` | View logs |
| `df` | Check disk space |
| `du` | Check directory usage |
| `free` | Memory usage |
| `ip` | Network information |
| `ping` | Connectivity testing |
| `ss` | Network connections |
| `dmesg` | Kernel messages |

---

# Troubleshooting Principles

Good troubleshooting should:

- Avoid guessing
- Use evidence
- Make one change at a time
- Record findings
- Verify fixes
